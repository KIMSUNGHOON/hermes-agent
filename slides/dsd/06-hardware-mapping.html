PROCESSOR — where the thinking happens
MEMORY & STORAGE — where knowledge lives
CPUcontrol plane · always-on
Agent loop · gateway process · Kanban dispatcher & claims · cron scheduler · tool orchestration · Python RPC. Light compute — runs on a $5 VPS.
GPUheavy inference
LLM inference, embeddings, image generation, TTS / voice. By default these hit provider APIs (GPU is provider-side); self-host on Ollama / vLLM for a private GPU.
NPUedge acceleration · optional
On-device small models & voice transcription on phones / Termux. Deployment-dependent — offloads light inference from the cloud, not required.
DRAMworking memory · fast · volatile
Active context window, conversation history, model KV-cache / loaded weights, in-flight tool results. Size-limited — the reason /compress & trajectory compression exist.
SSDhot persistent state · searchable
~/.hermes/ — SQLite memory DB (FTS5), SKILL.md library, kanban.db, session logs, model weights at rest. Survives restarts; queried before every reply.
HDDcold bulk storage
Archived session trajectories, batch-generated training datasets, backups. Rarely read, cheap per-GB — the agent's long-term cold store.
I/O · Network Model provider APIs  ·  messaging gateways (Telegram / Discord / Slack…)  ·  MCP servers  ·  remote terminal backends (SSH / Modal / Daytona)
Hermes' memory model is a hardware hierarchy: context = DRAM → memory DB + skills = SSD → trajectories = HDD.
